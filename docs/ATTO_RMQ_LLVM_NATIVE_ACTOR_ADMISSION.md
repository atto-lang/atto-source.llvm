# AttoRMQ native LLVM source actor admission

The `tests/fixtures/atto-rmq-native-preface-actor.atto` fixture is a **real** restricted source actor, not C++/Rust host logic. The production LLVM compiler lowers `spawn`, eight actor mailbox sends carrying the actual AMQP 0-9-1 preface octets, and `stop` into native LLVM IR. The Rust verifier links the generated IR with the actual native OresVM scheduler, actor heap and lifecycle implementations using Clang. It checks one exact VM receipt, eight accepted mailbox messages, FIFO prefix digest for the number of messages physically processed before STOP, no unexplained loss, native exit code and exact once actor heap release.

**Scope:** source-compiled `.atto` using the exact `use namespace rmq;` header and restricted inline actor syntax. The compiler now also admits the legacy `namespace rmq;` spelling, and rejects duplicate headers. This does not establish `declare actor` / `external mtd` execution. This is an incremental compiler-backed building block for the RabbitMQ clone, **not** native TCP AMQP preface execution. It does not perform authentication, tune/open, publish, consume, ACK, storage, or quorum. Actor messages are scalar `int`; `Bytes` mailbox ABI and socket-read `Future<Bytes>` lowering are unsupported here.

Source-native TCP/await remains fail-closed, as specified in `docs/ASYNC_ONLY_IO_CONTRACT.md`: host epoll/actor NIO readiness cannot be called from guest without typed capability, continuation and borrowing proofs. For actual full AttoRMQ LLVM parity, close those gates and run a true binary TCP client against a compiled `.atto` guest with namespace actor ingress and byte-buffer semantics. Do not benchmark this guest's process startup against the Java TCP preface performance; they are different operations.

This **must execute** the real production compiler, native linker, and executable with nonzero job steps before calling the native actor admitted. A queued/zero-step workflow is NOT_EXECUTED.
