# Owned pending Future native LLVM candidate

Explicit `atto-llvm input.atto -o guest.ll --owned-unwind-v1` emits native LLVM IR from the same owned source fixtures as Rust #742 and JS #121. Production lexer and bounded typed formal-slot parser, static continuation switches, no interpreter, heap, GC, or JIT. Caller supplies an aligned zero-initialized 26-i64 frame, exclusively owned by the logical invocation and never reused until external physical quiescence. Multiple independent frames may interleave; native functions are NOT thread safe and trusted host must serialize all accesses. Positive owner/epoch and error tokens are numeric host receipts, not authenticated authority. No native actor scheduler/continuation-store integration yet; direct C harness runs actual clang-linked guests. Terminal-only retire erases payloads and seals frame. Result query returns status and writes i64 via trusted output pointer; all other nonquery failures return -1. Status values match Rust candidate (pending=1, terminal=2; completion 0 value,1 failure,2 cancel; outcome 1 return,2 recover,3 raise,4 panic,5 cancel). Existing EffectUnwind has different legacy failure priority and is unchanged; integration needs a normative reconciliation. Not general typed MIR, arbitrary callback or STOP support. Keep draft pending independent review.
