# LLVM-owned Atto std/path, std/telemetry and std/sync — v1

The three sources in `stdlib/std/*.atto` belong to the LLVM compiler repository.
They are **backend-local**; they do not import the Java or .NET implementations.

## Supported source-level policies

- **path:** separator classification, safe UTF scalar and conservative Windows scalar checks, lexical component/dot/dotdot categories, checked depth change with 256-component budget, drive prefix, 4096-scalar input budget.
- **telemetry:** W3C version-00 *decoded fields* checks, OTel-style sampling decisions, timestamp windows, dormant precompiled AOT-probe admission, bounded batch admission and saturating drop counter.
- **sync:** lock acquisition/queue predicates, writer-priority reader admission, permit overflow-safe release, barrier and epoch transition checks.

## Non-claims and security boundaries

These files alone do **not** implement normalized path serialization,
symlink/root confinement, Unicode casefolding, trusted W3C wire parsing,
context propagation, OTLP networking, mutex/RWLock atomicity, lock ownership,
scheduler wakeups or actual semaphore/barrier scheduling. The necessary trusted
compiler/runtime backends must be implemented and tested independently.
No blocking APIs were added. No host language code was placed in these `.atto` files.

`tests/fixtures/stdlib_path_telemetry_sync_v1.atto` is a 44-branch
proposed guest behavior oracle. It is not a PASS until an exact-source
LLVM compiler imports all three modules and runs the guest. Unsupported
imports should fail explicitly rather than fall through to host behavior.

Related independent implementations: Java
`atto-source.java#1756` and .NET `atto-source.net#209`. No
byte-identity or cross-backend guest-parity claim is made.

## Follow-up audit and exact-source runner status (2026-11-22)
A new source audit verified that every fixture method exists in its backend-owned `.atto` module and no host-language source islands occur in those modules. Path scans reject unpaired Unicode surrogate scalars and values outside Unicode's maximum scalar range. The Java/.NET path views now scan one bounded Unicode snapshot per call and avoid temporary component arrays. Sync release and upgrade policy require an authenticated, unconsumed owner/generation receipt from a trusted runtime, not guest-created boolean authority.

**Verification boundary:** Guest fixtures are authored, not executed. Exact-current-head Actions jobs were queued or pending with no recorded runner steps when checked. Private-source export is not permitted merely by naming a carrier: Java has no active reviewed destination; .NET's candidate remains inactive; LLVM's stale StreemPilot allowlist entry is explicitly under the source-security hold described by LLVM #726/#736/#778. No private-source mirror was performed. Existing draft PRs must remain draft until stepful native guest results and all required reviews are available.

### Native compiler-owned import integration (follow-up)
The three LLVM-owned `.atto` files are now embedded under immutable generated C++ raw-string includes with pinned Git blob IDs, generated by the six-entry `tools/atto-library-embed` registry. `CoreLibrarySources.hpp` admits only exact `std/{path,sync,telemetry}`, `atto.std/` and `ores.std/` names (plus `.atto` suffix) as canonical singleton unit identities, with strict `Std` dependency tier and host-target gating in `ModuleLoader.cpp`. All other hosted std names, `.ores` suffixes, traversal and URI lookalikes are still rejected. The closed-registry C++17 probe now executes, and the native O0/O2 + ASan/UBSan workflow adds shadowing/freestanding negative cases. A C++ raw-string delimiter over 16 characters was caught and fixed before any build; the generator now rejects that case. The embedding was compared byte-for-byte to each exact `.atto` source blob: 3/3 match. **Source-level proof only**; actual runner-backed LLVM import/link and guest execution remain unverified.
